# المطلوب من الباك لإكمال خطط الأدمن وملف الطالب

## الموجود في العقد الحالي

| المسار | الموجود حالياً | ما يمنع إكمال تدفق اختيار الخطة ورفع PDF |
|---|---|---|
| `GET /admin/majors` | المسار موجود، لكن مخطط الرد عام ولا يحدد شكل عناصر التخصص | يلزم توثيق قائمة فيها `id` و`name` حتى يرسل الفرونت معرّف التخصص الصحيح من دون تخمين |
| `POST /admin/academic-plans` | إنشاء JSON بحقول مطلوبة `major_id`, `plan_name`, `plan_year`, `total_required_hours` واختيارية `college`, `degree`, `semesters_count` | لا يقبل PDF ولا يربط ملفاً بالخطة |
| `GET /academic-plans` | يعرض خطط الطالب، والخطة الجديدة يفترض أن تظهر بعد الإنشاء وإعادة الجلب | `AcademicPlan` لا يعيد بيانات ملف PDF أو طريقة فتحه |
| `GET /academic-plans/{id}/courses` و`/requirements` | قراءة مواد ومتطلبات الخطة | لا يوجد في العقد مسار أدمن لإضافة/ربط المواد والمتطلبات بالخطة الجديدة |

## المطلوب من علاء

1. توثيق شكل رد `GET /admin/majors` لتغذية قائمة التخصصات الـ11 الموجودة في بيانات البداية وربط كل اسم بـ`major_id` حقيقي.
2. دعم رفع PDF وربطه بالخطة. يمكن أن يحدد الباك إن كان ذلك عبر تعديل `POST /admin/academic-plans` ليقبل multipart مع حقول الخطة والملف، أو عبر تدفق رفع منفصل موثق. يجب تحديد التحقق من PDF وحد الحجم والتخزين والاستجابة.
3. إتاحة الملف للطالب من خلال بيانات أو طريقة تنزيل موثقة؛ لا يوجد حالياً حقل ملف في `GET /academic-plans`.
4. إذا كان المطلوب أن يعرض المسار الأكاديمي مواد الخطة أيضاً، توثيق عملية أدمن لإضافة مواد ومتطلبات الخطة. المسارات الموجودة للطالب تقرأها، وPATCH الأدمن يعدّل فصل مادة مرتبطة بالفعل فقط.

## وضع الفرونت

- يعرض النموذج اختيار الخطط الأصلية الموجودة في `initialStudyPlans` وعددها 11، ويزيل الإدخال اليدوي لـ`major_id`.
- يقرأ قائمة تخصصات الأدمن ويتحقق من شكل `id/name` لمطابقة الخيار. الخيار الذي لا يطابق تخصصاً من الخادم يبقى معطلاً.
- يوفر اختيار ملف PDF، لكن زر الحفظ معطل إلى أن يدعم العقد حفظ الملف وربطه. لا يتم إرسال ملف أو إظهار نجاح وهمي.
- بعد أن يدعم الباك الرفع وإرجاع بيانات الملف، يجب وصل الملف برد `/academic-plans` أو مسار تنزيل موثق ليظهر فعلياً للطالب.
