# دليل تجربة UniMeta للمطوّر

## المستودع والفرع

- المستودع: <https://github.com/saja-abo-hassn/UniMeta>
- الفرع المطلوب: `feat/connect-backend`
- الواجهة: Next.js 16.4.5، والاعتمادات مثبتة في `package-lock.json`.

## المتطلبات

- Node.js 20.9 أو أحدث (هذا الحد مأخوذ من `engines` لحزمة Next.js الموجودة في المشروع).
- npm 9 أو أحدث لدعم `package-lock.json` ذي الإصدار 3. النسخة التي فُحص بها المشروع: Node.js 24.11.1 وnpm 11.6.2.

## الاستنساخ والتحديث

```bash
git clone -b feat/connect-backend https://github.com/saja-abo-hassn/UniMeta.git
cd UniMeta
npm ci
```

لتحديث نسخة موجودة:

```bash
git switch feat/connect-backend
git pull origin feat/connect-backend
npm ci
```

## إعداد البيئة والتشغيل

في PowerShell:

```powershell
Copy-Item .env.example .env.local
```

افتح `.env.local` محلياً واضبط المتغيرات:

- `BACKEND_API_URL`: عنوان API محلي أو staging مصرح به وينتهي بـ `/api/v1`. اتركه فارغاً إذا كنت تشغّل الواجهة دون باك؛ عندها ستظهر أخطاء إعداد الاتصال بوضوح.
- `NEXT_PUBLIC_USE_MOCK=false`: يستخدم API عبر BFF. اضبطه على `true` لعرض الواجهة التجريبية المحلية فقط؛ بيانات mock لا تثبت عمل الربط الحقيقي.
- `NEXT_PUBLIC_SITE_URL=http://localhost:3000`: أصل الواجهة المحلية.
- `BFF_SHARED_SECRET`: اختياري محلياً حسب إعداد Laravel، ويجب الحصول عليه من مسؤول الباك عبر قناة آمنة. لا تحفظ قيمته في Git أو ترسلها في المحادثة.
- `NEXT_PUBLIC_LIBRARY_MAX_MB=20`: حد رفع المكتبة الذي تعرضه الواجهة.

لا تستخدم عنوان الإنتاج لاختبار تدفقات الدخول أو الرسائل أو أي عملية تغيّر بيانات. استخدم staging وحسابات اختبار صادرة عن الفريق. لا تضع مفاتيح أو كلمات مرور حقيقية في هذا الملف أو في GitHub.

ثم شغّل:

```bash
npm run dev
```

افتح <http://localhost:3000>.

## تجربة الوظائف

- **تسجيل الدخول والخروج:** يحتاجان حساب staging مناسباً؛ لا تختبرهما على الإنتاج. جلسة API تحفظ في Cookie من نوع HttpOnly عبر BFF.
- **لوحة الطالب:** جرّب القراءة ببيانات حساب طالب staging. بعض الصفحات تتطلب بيانات تخص الحساب.
- **لوحة الأدمن:** تحتاج حساب أدمن staging. صلاحية الأدمن تُحمّل من ملف المستخدم؛ المشرف وصلاحياته تعتمد على عقد الباك وحسابه.
- **Chatbot:** افتح أداة المحادثة وأرسل سؤالاً فقط عند ضبط staging. الضيف يستخدم `POST /ai/assistant`، والمستخدم المسجّل يستخدم جلسات `/ai/sessions`. استجابة العقد غير موصوفة تفصيلياً بعد؛ أبلغ عن endpoint والحالة والوقت، مع حذف البريد والرموز وأي بيانات حساسة من السجلات.
- **المكتبة:** قراءة الطالب تستخدم `/library/subjects` ومواردها الظاهرة. لوحة الأدمن تقرأ موارد ومواد المكتبة؛ نماذج الرفع والتعديل ما زالت معطلة في الواجهة الحالية رغم وجود بعض المسارات في OpenAPI.

## معرفة أخطاء الاتصال

1. افتح أدوات المطوّر ثم تبويب **Network**.
2. افحص طلبات `/api/backend/...`؛ سجّل المسار والطريقة والحالة والوقت فقط.
3. رسالة الواجهة عند انتهاء المهلة أو انقطاع الشبكة تخص الاتصال بين المتصفح وBFF أو بين BFF والباك. BFF يمرر حالة Laravel؛ HTTP 500 يحتاج فحص سجلات Laravel وخدمة الذكاء الاصطناعي لدى فريق الباك.
4. لا تشارك Cookies أو Bearer tokens أو أسرار BFF أو محتوى رسائل خاصة في تقرير الخطأ.

## ما يعمل وما لم يكتمل

- صفحات الواجهة ومكونات تسجيل الدخول تتصل عبر Next.js BFF؛ الاختبارات المحلية تستخدم mocks.
- تدفق تأكيد البريد وصفحات الحساب موجودة، ويجب اختبارها بحساب staging.
- Chatbot يعرض أخطاء الاتصال ويدعم إعادة المحاولة، لكن استجابة AI الفعلية وسبب خطأ 500 لم يتم التحقق منهما على staging.
- تفاصيل المواد وربط رمز المادة مدعومة بعقد API (`subject_code` و`subject_id`)، لكن الإدخال اليدوي ورفع الملفات والنشر من لوحة الأدمن ليست موصولة بالكامل في الواجهة.
- بعض عمليات التبادل والمساهمة والمحتوى تبقى محدودة حسب عقد OpenAPI؛ راجع [فجوات الباك إند](backend-gaps.md).
- نجاح البناء أو اختبارات mocks لا يثبت نجاح الخادم الفعلي. تحقق من عمليات الكتابة في staging فقط.

## أوامر الفحص

```bash
npx tsc --noEmit
npm run lint
npm run build
npm run test:api
```

تشغيل `test:api` يتم محلياً باستخدام mocks ولا يحتاج بيانات دخول. لا تشغّل اختبارات POST أو PUT أو PATCH أو DELETE على API الإنتاج.
